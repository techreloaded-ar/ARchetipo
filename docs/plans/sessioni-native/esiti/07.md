## Stato

View mostra e invoca nel composer soltanto le skill dichiarate dal runtime della
sessione corrente. La selezione entra nello stesso turn e nella stessa sessione
nativa, senza creare una execution o avviare un secondo agente.

## Risultato e contratti modificati

- `execution.SessionSkill` conserva `name`, `description`, `path`, `namespace`,
  `origin` e la forma di `invocation`; `SessionDiscovery.skills_known` distingue
  un catalogo autorevole vuoto da uno non ancora osservato.
- Codex usa `skills/list` con `forceReload`, scarta `enabled:false`, conserva
  `scope`, deriva il namespace senza riscrivere il nome e usa sia il marker
  `$name` sia l'input nativo `{type:"skill", name, path}`. Sulle sessioni
  connesse la discovery riusa l'app-server esistente; `skills/changed` invalida
  la vista e provoca una nuova lettura.
- Claude usa l'intersezione fra `system/init.skills` e
  `system/init.slash_commands`: una skill non esplicitamente invocabile non entra
  nel menu. L'invocazione usa `/name` come primo contenuto del turn. Il catalogo
  resta `skills_known:false` prima del primo `system/init`, perché Claude Code
  2.1.266 non offre una richiesta di discovery equivalente a `skills/list`.
- `GET /api/workspace/conversations/{id}/model-choice` espone il catalogo con
  provider, cwd e ambiente già vincolati alla sessione. Un errore lascia alla UI
  l'ultimo catalogo noto e non viene convertito in un elenco vuoto.
- Il composer usa un `<select>` nativo. Il browser invia soltanto il nome; il
  server rilegge il catalogo e risolve il riferimento completo prima di
  `StartTurn`, rifiutando nomi stale e skill durante steering.
- Alla chiusura di un turn View rilegge catalogo e board. Gli effetti prodotti
  dalla skill sono quindi mostrati dallo stato reale del workspace, senza
  execution obbligatoria.

- `waitLiveCodexNativeState` esce dichiarando lo stato e l'errore quando il turno
  raggiunge uno stato terminale diverso da quello atteso. Prima un turno fallito
  faceva scadere il probe dopo dieci minuti senza dire cosa fosse successo: è
  così che il fallimento per crediti esauriti si presentava come un blocco.

Le fixture coprono skill solo Claude, solo Codex, condivisa, disabilitata e con
namespace plugin. Directory dell'altro harness non vengono mai scandite: Codex
segue il proprio `skills/list`, Claude il proprio `system/init`.

La skill `ponytail` ha mantenuto il lavoro sul contratto discovery e sul
composer esistenti: nessun endpoint aggiuntivo, watcher parallelo, parser di
`SKILL.md` o dependency frontend.

## Regole precedenti eliminate e decisioni

- Eliminata la scansione `.claude/skills`: non rappresentava skill personali,
  plugin, precedenze, disabilitazioni o invocabilità effettive.
- Il frontend non legge mai il corpo di una skill e non costruisce path.
- Una skill nativa non apre una proposta, una execution o una conversation
  secondaria.
- Un catalogo Claude non ancora annunciato è dichiarato sconosciuto; non viene
  completato con skill ipotetiche.

## Limiti e handoff

- Claude Code 2.1.266 pubblica soltanto i nomi nel frame di init: descrizione,
  path e scope non sono attribuiti. Il namespace resta quello presente nel nome
  runtime. Prima del primo turn, e dopo un restart di View fino al primo nuovo
  init, il menu dichiara il catalogo non ancora noto.
- Claude non espone una notifica di modifica catalogo nello stream provato; il
  catalogo viene aggiornato a ogni nuovo `system/init`. Codex espone invece
  `skills/changed` e viene aggiornato immediatamente.
- La prova live Codex resta da ripetere: il criterio "il risultato del tool
  dimostra l'invocazione nella stessa sessione" è dimostrato su runtime reale
  soltanto per Claude, e sul fake per Codex. Non è un limite del codice ma della
  disponibilità del runtime alla consegna.
- Il task 08 può passare la skill di processo allo stesso `SessionTurn` usando
  `StartTurnRequest.Skills`; non deve aprire una execution separata soltanto per
  ottenere l'invocazione nativa.
- Le modifiche preesistenti dell'utente in `.archetipo/config.yaml`, mockup e
  probe console sono state preservate e restano fuori dal commit.
